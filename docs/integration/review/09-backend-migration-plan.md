# Backend Migration Plan

> Review copy: historical evidence from the tested feature branch based on `a55b56e`, not an audit of current upstream `main`. Workstation paths/device identifiers are omitted. Original local documents are preserved outside this commit scope. See [review guide](README.md).

Audit date: 2026-10-14. **Planning only: implementation requires user/team review and approval.** Canonical backend is Daniel's implementation; one logical PostgreSQL database per environment, all clients share canonical identities and business records. No reference backend retirement, data import, contract change or moderation change has been performed.

Inputs: [feature parity](06-backend-feature-parity-matrix.md), [Android audit](07-android-integration-audit.md), [inspection workflow](08-farmer-inspection-verification-audit.md), [decisions/risks](10-open-decisions-technical-risks.md), [prior demo verification](05-local-demo-verification.md). Relative effort is implementation + relevant tests: small (bounded adapter/test), medium (cross-layer capability), large (business state/data/security across clients); not a calendar promise.

## Architectural choice

Use **A + B**: adapt Android to canonical contracts, extend canonical only for missing required behavior. **C** (selected reference behavior) is useful as specification/test evidence for rotation, soft unlisting, participant checks, seller orders, inspection/report structure and events. Port no complete UUID modules or schemas. Both repositories have flaws; reference source is not a security gold standard. Preserve existing web/admin envelopes, aliases, IDs, field spelling, enums, pagination and behavior until actual clients are inspected and changes explicitly accepted.

Product approval is **PENDING TEAM DECISION**. Keep pending creation, status transitions, visibility and purchasing eligibility unchanged in all phases until a separately approved policy change. A confirmed existing owner-status bypass must be reviewed and tested; closing it is still a behavior change requiring explicit agreement, not an audit-time patch. Farmer verification is a separate required workflow and does not decide product policy.

## Phase 6 — Cross-client validation and Daniel review

Prerequisites: actual web/admin repositories/configuration available; feature scopes and deferred features signed off; migration inventory and staging/local identity approved. Large phase, separate small reviewable PRs preferred.

1. Capture each real client API contract and environment URL. Verify Android, web and admin use the same C backend/database, not just similarly named deployments. Test shared farmer/product/inspection/order IDs across clients with authorization/moderation.
2. Build replayable canonical baseline and ordered migrations; compare with existing schema, never blindly execute historical scripts. Prepare **separate reviewed** reference data export/import: UUID→Long mapping persisted per entity, identity deduplication, decimal quantity exception report, statuses mapped by team, CustomerOrder/seller relations, private evidence/image OID/files/storage move, history/audit retention. No permanent dual database or duplicate tables. Backups and dry-run validation before any actual import; passwords/tokens not blindly imported, refresh sessions invalidated under agreed cutover policy.
3. Execute regression suites in approved isolated test environment: positive/negative roles, refresh/replay/recovery, stock concurrency, moderation visibility, inspection final review, checkout/payment callbacks/delivery/refunds. Preserve existing dev fixture records; opt-in smoke tests create unique records only when explicitly needed. Test whole web/admin UI against C.
4. Review changes/diffs and generated artifacts, omit credentials/local configs/APKs/build output from commits, document migrations/rollback/limitations. Do not mix pre-existing reference changes into C review. Daniel reviews canonical contract/security/business decisions before merge. User approval still required to commit/push/share.

Exit/retirement gate for R: no intended client uses legacy endpoints/UUID identities; required features supported or explicitly deferred; real data reconciliation complete with no orphans/money/quantity loss; approved migrations reproducible; all clients and provider sandbox pass; rollback and operational ownership agreed. Retire R only after an explicit cutover decision, never as a side effect of Android flag changes.

## First recommended implementation task
